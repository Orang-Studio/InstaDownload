# Contributing to InstaDownload

Thanks for wanting to help. Contributions are welcome, from bug reports to code.

## Before you write code

- **Open an issue first for big changes**, so we can agree on the approach before you spend time on it. Bug fixes, typo fixes and small self-contained features can go straight to a PR.
- Check existing issues and PRs to avoid duplicating work.

## Pull requests

- **Keep them small and focused.** One change per PR. If it is hard to review in one sitting, it is too big, so split it up.
- Don't include unrelated changes such as reformatting, line-ending changes or renamed files.
- Don't leave temporary files, debug code or experimental CI jobs in the PR.
- Say what the change does and why, in your own words.
- Test it on a real device or emulator and tell us which Android version you used.
- Follow the style of the surrounding code.

## AI-assisted code

We allow AI-generated and AI-assisted code. It can be a great way to speed up hard tasks like reverse engineering, chasing a difficult bug or scaffolding something new. We only ask that you stay the author:

- **You must understand every line you submit** and be able to explain and defend it in review.
- **Review it yourself first.** Read the diff, run the app and fix what the tool got wrong before you open the PR.
- **Say so in the PR** if AI wrote a significant part of it. A `Co-Authored-By` line in the commit is fine.
- **Write the PR description yourself.** A generated wall of text doesn't help a reviewer.
- **Match the scope to what a human can review.** Large AI-generated drops, especially with no earlier discussion, will be closed even if the idea is good.

If a PR looks mostly generated and unreviewed, we may close it and implement the idea ourselves. We will credit you for the idea.
